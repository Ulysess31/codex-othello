# 오델로 웹 게임 설계 문서

## 1. 개요

- **목표:** 브라우저에서 바로 실행할 수 있는 간단한 2인용 오델로 게임을 만든다.
- **대상:** 같은 화면에서 번갈아 두는 플레이어. 온라인 대전과 계정 기능은 초기 범위에 포함하지 않는다.
- **플랫폼:** 데스크톱과 모바일 브라우저에 대응하는 반응형 웹 페이지.
- **주요 학습 목표:** 게임 기능을 많이 추가하는 것보다 React 프로젝트의 폴더와 파일 역할, Node.js/npm/Vite 같은 개발 환경, 화면과 규칙 코드의 연결, 단계별 구현·검증·기록 방법을 이해하는 데 더 큰 비중을 둔다.
- **기능 수준:** 학습에 필요한 기본 오델로 기능을 간결하게 구현한다. 실제 서비스 수준의 고급 기능이나 불필요한 최적화보다 읽기 쉽고 흐름을 따라가기 쉬운 코드를 우선한다.

## 2. 핵심 게임 규칙

- 8×8 보드에서 흑과 백이 번갈아 돌을 둔다. 시작 배치는 중앙 네 칸에 흑 2개와 백 2개를 대각선으로 놓는다.
- 상대 돌을 자신의 돌로 양쪽에서 포위할 수 있는 칸에만 둘 수 있다. 가로·세로·대각선으로 포위된 상대 돌은 모두 자신의 색으로 뒤집는다.
- 둘 수 있는 곳이 없으면 차례를 넘긴다. 양쪽 모두 둘 수 없거나 보드가 가득 차면 게임을 끝낸다.
- 종료 시 돌이 더 많은 플레이어가 승리하며, 같으면 무승부다.

## 3. 주요 화면과 동작

1. **게임 화면:** 8×8 보드, 현재 차례, 흑·백 돌 개수, 가능한 수 표시, 새 게임 버튼을 제공한다.
2. **수 두기:** 유효한 칸을 선택하면 돌을 놓고 포위된 돌을 뒤집은 뒤 차례를 갱신한다. 무효한 칸은 보드를 변경하지 않고 안내한다.
3. **차례 건너뛰기:** 현재 플레이어가 둘 곳이 없으면 자동으로 차례를 넘기고, 사용자에게 알린다.
4. **게임 종료:** 승리·패배·무승부와 최종 돌 개수를 보여주고 다시 시작할 수 있게 한다.
5. **새 게임:** 초기 보드와 차례, 결과 안내를 초기화한다. 진행 중인 게임을 초기화하기 전에 확인을 요청한다.

## 4. 인터랙션 및 접근성

- 가능한 칸은 빈 칸과 구별되는 표시로 안내하되 색상만으로 구분하지 않는다.
- 보드 칸은 키보드로 탐색하고 선택할 수 있게 하며, 칸 좌표와 상태를 보조 기술에 전달한다.
- 터치 화면에서도 칸을 쉽게 선택할 수 있도록 보드와 칸 크기를 반응형으로 조정한다.
- 현재 차례, 자동 패스, 잘못된 수, 게임 종료 메시지는 화면에서 명확히 알린다.

## 5. 데이터 및 상태

- `board`: 8×8 배열. 각 칸은 빈 칸, 흑, 백 중 하나다.
- `currentPlayer`: 현재 차례(`black` 또는 `white`).
- `legalMoves`: 현재 플레이어가 둘 수 있는 칸 목록. 매 수 이후 보드 상태에서 계산한다.
- `status`: 진행 중, 종료 상태와 승자 또는 무승부 정보.
- 돌 개수는 보드에서 계산해 표시한다. 게임 중 서버 저장이나 영속 저장은 필요하지 않다.

## 6. 구현 원칙

- 합법 수 탐색과 돌 뒤집기를 UI 코드와 분리해 독립적인 게임 로직으로 구현한다.
- 보드 변경은 합법 수 검증 후 한 번에 반영해 부분 업데이트를 방지한다.
- 별도 백엔드 없이 클라이언트에서 동작하도록 구성한다. 구체적인 프레임워크와 시각 디자인은 구현 단계에서 프로젝트 환경에 맞춰 정한다.
- **초보자와 AI가 함께 개발하는 프로젝트:** 각 작업을 작은 단계로 나누고, 구현 전에 이번 작업이 무엇을 만들며 왜 필요한지 쉬운 말로 설명한다. 작업을 마친 뒤에는 바뀐 파일과 동작, 실행한 검증 및 결과를 초보자도 이해할 수 있게 요약한다.
- 중요한 규칙이나 처음 보면 이해하기 어려운 코드에는 한국어 주석을 달아 의도와 이유를 설명한다. 코드 한 줄을 그대로 한국어로 반복하는 주석은 피한다. 예를 들어 “상대가 둘 곳이 없으면 이번 차례를 넘긴다”처럼 게임 규칙이나 선택 이유를 설명한다.
- 새 파일이나 컴포넌트를 만들 때는 파일이 맡는 역할과 다른 코드와 연결되는 방식을 `architecture.md`에 설명한다. 새 도구를 쓰면 이름만 나열하지 말고 어떤 일을 돕는지 함께 설명한다.
- 단계별 검증은 실제로 실행한 결과와 함께 무엇을 확인했는지, 왜 필요한지 기록한다. 아직 실행하지 않은 검증은 완료로 표시하지 않고 예정으로 구분한다.
- 설명은 초보자의 이해를 돕되 정확한 파일명, 함수명, 터미널 명령은 그대로 제공해 직접 따라 해볼 수 있게 한다.
- **학습 우선순위:** 작업의 우선순위는 1) 프로젝트 진행 방법과 개발 환경 이해, 2) 각 폴더·파일의 역할과 프로그램 데이터 흐름 이해, 3) 필수 게임 동작 구현 순으로 둔다. 게임은 프로젝트 구조와 개발 과정을 배우기 위한 작은 실습 재료다.
- **기능은 기초 수준으로 제한:** 설계 문서의 기본 규칙과 화면 흐름을 구현하되 AI 상대, 온라인 기능, 계정, 저장, 복잡한 애니메이션, 범용 게임 엔진처럼 학습 목표에 필요하지 않은 기능은 추가하지 않는다. 요청이 없는 한 더 정교한 추상화나 성능 최적화도 넣지 않는다.
- **설명 가능한 단순함:** 코드는 한 번에 이해하기 쉬운 함수와 컴포넌트로 구성한다. 짧은 코드보다 구조와 데이터가 어떻게 이동하는지 설명하기 쉬운 코드를 택하고, 새 도구·파일·패턴을 추가할 때는 필요한 이유와 대안을 쓰지 않은 이유를 간단히 설명한다.
- 각 단계의 결과를 설명할 때 게임 동작뿐 아니라 이 작업으로 익힐 프로젝트 개념(예: npm 명령, 컴포넌트 책임, 상태 흐름, 테스트 목적)을 함께 안내한다.

## 7. 완료 기준

- 초기 배치와 합법 수 판정, 여러 방향의 뒤집기가 규칙대로 동작한다.
- 둘 곳이 없는 상황의 패스와 양쪽 모두 둘 곳이 없는 종료가 처리된다.
- 점수와 승패가 정확하며 새 게임으로 정상 초기화된다.
- 데스크톱·모바일에서 사용할 수 있고 키보드와 보조 기술로 핵심 게임을 진행할 수 있다.
