# 오델로 웹 게임 구현 계획

## 목표

`design-document.md`에 정리된 규칙을 따르는 반응형 2인용 오델로 게임을 구현한다. `AGENTS.md`의 기술 규칙에 따라 React와 JavaScript로 화면을 만들고, 게임 로직은 UI에서 분리한다. 이 계획은 구현 순서와 각 단계의 완료 조건을 정한다.

## 범위

포함: 8×8 게임 보드, 흑·백 차례, 합법 수 안내, 착수와 뒤집기, 자동 패스, 종료·점수·결과, 새 게임, 키보드와 보조 기술 지원, 반응형 레이아웃.

초기 버전에서 제외: 온라인 대전, 계정, 서버, AI 상대, 게임 기록 저장, 애니메이션 의존성 및 별도 디자인 시스템.

## 기술 및 구조 결정

- React 함수형 컴포넌트, JavaScript, JSX, 일반 CSS, Vite, npm을 사용한다.
- 규칙 로직은 `src/game/othello.js`의 순수 함수로 구현하고 Vitest로 검증한다.
- 화면은 `App.jsx`, `components/Board.jsx`, `components/GameInfo.jsx`로 나눈다. 상태는 우선 `App.jsx`에서 관리한다.
- `legalMoves`와 점수는 보드에서 파생해 표시한다. 같은 정보를 별도 상태로 중복 보관하지 않는다.
- 초기화 확인은 브라우저 기본 `window.confirm`을 사용해 추가 UI 의존성을 피한다.
- 새로운 패키지는 꼭 필요한 경우에만 추가하고 `package-lock.json`을 커밋 대상에 포함한다.

## 구현 단계

### 1단계: 프로젝트 기반 구성

**작업**

- Vite React 프로젝트와 `index.html`, `src/main.jsx`, `src/App.jsx`를 구성한다.
- ESLint와 Vitest를 설정하고 다음 npm 스크립트를 만든다: `dev`, `build`, `preview`, `lint`, `test`.
- `src/components`, `src/game`, `src/styles` 디렉터리를 만든다.

**완료 조건**

- `npm run dev`로 개발 페이지가 열린다.
- `npm run lint`, `npm run test`, `npm run build`가 실행 가능한 초기 설정을 갖춘다.

### 2단계: 오델로 규칙 엔진 구현

**작업**

- `createInitialBoard`, `getFlips`, `getLegalMoves`, `applyMove`, `getNextTurn`, `countDiscs`를 작성한다.
- 보드는 8×8 배열, 빈 칸은 `null`, 돌은 `'black'` 또는 `'white'`로 표현한다.
- 착수 검증 후 새 보드를 반환하며 입력 보드는 변경하지 않는다.
- 상대 차례에 둘 곳이 없으면 자동 패스한다. 상대와 현재 플레이어 모두 둘 곳이 없으면 보드가 가득 차지 않았어도 종료한다.
- 게임 결과는 돌 개수로 승리·패배·무승부를 결정한다.

**검증 사례**

- 초기 배치가 D4·E5 백, E4·D5 흑이며 흑의 초기 합법 수가 4개다.
- 가로, 세로, 대각선 및 한 번의 수에서 여러 방향의 뒤집기를 확인한다.
- 보드 경계, 빈 칸이 아닌 위치, 포위가 성립하지 않는 위치를 확인한다.
- 합법 수 적용이 새 보드를 만들고 입력 보드를 유지하는지 확인한다.
- 상대 패스, 양쪽 모두 착수 불가, 빈 칸이 남은 종료를 확인한다.
- 흑 승리, 백 승리, 동점 결과와 돌 개수를 확인한다.

### 3단계: 게임 화면과 상태 연결

**작업**

- `App.jsx`가 초기 보드와 현재 플레이어, 진행 상태, 사용자 안내 메시지를 관리한다.
- `Board.jsx`에서 64개 칸을 좌표 기반의 고정 key로 렌더링한다.
- 합법 수에 시각 표시를 추가하고 보드 칸 선택을 상위 이벤트로 전달한다.
- 유효한 착수 후 보드와 차례, 패스/종료 상태를 한 번의 상태 갱신으로 반영한다.
- 무효한 선택은 보드를 바꾸지 않고 안내 메시지만 표시한다.
- `GameInfo.jsx`에서 흑·백 점수, 현재 차례, 상태 메시지, 종료 결과를 표시한다.
- 새 게임 버튼은 진행 중일 때 초기화 여부를 확인하고, 새 게임 상태에서는 확인 없이 초기화한다.

**완료 조건**

- 브라우저에서 시작 배치부터 종료까지 한 게임을 진행할 수 있다.
- 차례 표시, 합법 수, 점수, 패스, 최종 결과가 보드 상태와 일치한다.

### 4단계: 반응형 디자인과 접근성

**작업**

- 보드를 CSS Grid로 만들고 화면 폭에 맞춰 정사각형을 유지한다.
- 칸을 좌표와 돌 상태를 설명하는 버튼으로 구현한다.
- 키보드 방향키 이동과 Enter/Space 착수를 지원하고 Tab 진입점은 보드당 하나로 관리한다.
- 현재 차례, 합법 수, 포커스, 빈 칸을 색상 외의 형태·문구로 구분한다.
- 안내·패스·결과는 `aria-live="polite"`로 알린다.
- 좁은 화면에서도 가로 스크롤이 생기지 않도록 보드와 주변 여백을 조정한다.

**완료 조건**

- 마우스, 터치, 키보드로 주요 게임 흐름을 사용할 수 있다.
- 칸 좌표와 상태가 보조 기술에서 구별되며 포커스 표시가 명확하다.
- 데스크톱과 모바일 폭에서 보드와 점수 영역이 읽기 쉽다.

### 5단계: 최종 점검 및 문서화

**작업**

- `npm run test`, `npm run lint`, `npm run build`를 실행하고 발견한 오류를 수정한다.
- `npm run preview`로 빌드 산출물을 확인한다.
- 새 게임 확인, 무효한 수 안내, 자동 패스, 종료 메시지를 수동으로 확인한다.
- 키보드 탐색 및 좁은 뷰포트에서 기본 플레이가 가능한지 확인한다.
- README가 없으면 실행 명령을 담은 짧은 `README.md`를 추가한다.

**완료 조건**

- 자동 검사 명령이 통과하고, 수동 확인에서 핵심 완료 기준을 만족한다.
- 저장소에 실행 방법과 구현 상태를 확인할 수 있다.

## 구현 시 주의할 규칙

- 좌표는 내부적으로 0부터 시작하고 화면은 A1부터 표기한다. 행·열 변환을 한 곳에서 처리한다.
- 새 게임 초기화 시 보드, 차례, 진행 상태, 안내 메시지를 함께 초기화한다.
- 이미 끝난 게임에서는 착수를 받지 않는다.
- 점수와 합법 수를 칸마다 반복 계산하지 말고 화면 렌더링 단계에서 한 번 계산해 전달한다.
- 접근성 기능은 마지막에 덧붙이는 항목이 아니라 보드 컴포넌트 구현 시 함께 반영한다.
- 사용자가 기획을 바꾸면 이 계획과 `design-document.md`, 필요 시 `AGENTS.md`를 함께 갱신한다.
